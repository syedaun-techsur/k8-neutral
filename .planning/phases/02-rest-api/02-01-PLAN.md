# Plan 02-01: Health Endpoint

**Plan:** 01 of 3

## Context

Phase 1 created the Next.js 14 scaffold (`next.config.mjs`, `app/layout.tsx`, `app/page.tsx`) and the database module (`lib/db.ts`). No API routes exist yet.

This is the simplest endpoint — a pure liveness probe that must NOT touch the database. It must return `200 {"status":"ok"}` unconditionally.

## Pre-conditions

- `app/` directory exists
- `next.config.mjs` exists (never `next.config.ts`)
- No `app/api/` directory exists yet

## Tasks

### Task 1: Create `app/api/health/route.ts`

Create the directory structure and the health route file.

**File:** `app/api/health/route.ts`

```ts
import { NextResponse } from 'next/server';

export async function GET() {
  return NextResponse.json({ status: 'ok' });
}
```

**Rules:**
- Do NOT import from `lib/db` — this endpoint has zero database dependency
- Do NOT `await ready` — the health check must return 200 even if the DB is down
- No `NextRequest` parameter needed (no request data consumed)
- `NextResponse.json({ status: 'ok' })` defaults to HTTP 200

**Commit:** `feat(02-01): add GET /api/health endpoint`

## Verification

After the task, verify:

1. File exists: `app/api/health/route.ts`
2. The file does NOT import from `lib/db`
3. `curl http://localhost:3000/api/health` returns `{"status":"ok"}` with HTTP 200

## Success Criteria
